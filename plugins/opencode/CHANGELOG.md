# Changelog

## Unreleased — 0.2.0

- **Contract change.** Runs are now classified three ways instead of pass/fail. A run that exits 0 without producing an answer is `incomplete`, not `completed`: empty final text, a stop reason that is not a finished turn (`tool-calls`, `length`, `aborted`, …), or a very short final message after tool calls on a large prompt. `incomplete` runs exit with code **2** (failures keep 1), get the job status `incomplete`, and render through a dedicated renderer that labels the partial output as work-in-progress, prints the tail of stderr (which is where opencode reports auto-rejected paths), and gives a `/opencode:rescue --resume` recovery command. `task`/`review` `--json` now include `outputState`, `outputStateReason`, `stopReason` and `toolEventCount`; `status`/`result` detail show the output state and stop reason. Unknown stop reasons only warn on stderr — they never downgrade a run. The narration heuristic threshold is `OPENCODE_COMPANION_MIN_ANSWER_CHARS` (default 200).
- **Contract change.** Job records are reconciled against process liveness whenever they are read (`status`, `result`, `cancel`, the Stop and SessionEnd hooks). A `running`/`queued` record whose child pid is gone — or that never recorded one and has been untouched for longer than the 120s grace window — is rewritten as `failed` with `failureClass: "orphaned"`, an end timestamp, and elapsed time frozen at the last sign of life instead of growing forever. `status`/`result` render it as `failed (orphaned)` and point at the job log plus `/opencode:rescue --resume`; `status --wait` now returns as soon as a job reaches a terminal state instead of polling a dead record for the full 15 minutes. Reconciliation only relabels — killing processes stays with `cancel` and session teardown.
- **Contract change.** `task`, `review` and `adversarial-review` no longer swallow `--background`: they exit 1 with `--background is a Claude Code execution flag, not a companion flag; the companion always runs in the foreground. Detach with Bash(run_in_background: true), or use /opencode:rescue --background.` Passing it used to look like a successful detach while the run was still on Claude Code's 2-minute Bash wall that then killed it. `--wait` stays an accepted no-op — the companion is a foreground runner, which is what it asks for. The two review slash commands now strip both flags before building the companion command line.
- `task`/`review`/`adversarial-review` accept `--timeout-ms <ms>` (default 900000). `opencode run` has no timeout flag of its own, so this is the only deadline a stuck run has: at the deadline the companion terminates the child's process group and records `failed` with `failureClass: "timeout"`, and the failure render says how long it waited. `result` accepts `--wait` and `--timeout-ms` (default 900000), blocking until the job reaches a terminal state and then printing the same output — the primitive the hand-written `for i in $(seq 1 180)` polling loops were emulating. `--help` now lists `--timeout-ms` and states that `--background`/`--wait` are Claude-side flags.
- `--help` / `-h` is now handled per subcommand and intercepted before dispatch, so `task --help` prints the companion's own flags instead of being forwarded to opencode as the prompt. It used to cost a real model turn and come back as a *model-generated* help page for the opencode CLI — describing flags this companion has never had — and one of those runs was stored as a `completed` job. A `--flag` that appears before any free text and is not in the subcommand's spec now fails the run (`Unknown flag: --wrote. Run 'task --help' for supported flags.`) instead of being sent as prompt text; dashes *inside* task text stay task text, and `--` ends flag parsing so anything after it is literal.
- The companion now handles `SIGTERM`/`SIGINT`/`SIGHUP`. It had none, and opencode is spawned detached, so a Bash timeout killed the companion and left the opencode child running (one 2026-07-17 incident needed `kill -9` on two pids by hand) with the job record frozen at `running` and nothing stored. The handler kills the child's process group, records `failed` with `failureClass: "interrupted"`, stores whatever opencode had streamed so far so `/opencode:result <id>` still shows the partial output, and then re-raises the signal with its default disposition so the exit status stays truthful (143 for SIGTERM). It never overwrites a job that already reached a terminal state, so it is idempotent with `cancel` and session teardown.
- `task`, `review` and `adversarial-review` print the job handle *before* opencode starts (`Job: <id> (task, running) — poll with /opencode:status <id>`; a JSON line on stderr under `--json`, so stdout stays a single document). The id previously appeared only in the footer after the run, so the 28 recorded runs that were detached with `Bash(run_in_background: true)` had no handle to poll while they were in flight and grew hand-written shadow job control instead.
- `task` gained `--prompt-file <path>` and `--prompt-stdin`, and in the single-argument form everything after a standalone `--` is now passed through byte for byte instead of being tokenized. The documented `task "<prompt>"` shape ran the prompt through a tokenizer that drops quote characters, truncates at an apostrophe and folds newlines into spaces — 8 of 39 recorded `task` calls used exactly that shape, all of them carrying quoted, multi-line review contracts. Passing both a prompt source and free text is now an error rather than a silent drop. The rescue skill and agent document `-- <prompt>` and `--prompt-file` as the supported forms.
- An auto-rejected opencode permission is now a typed warning instead of a line the caller had to notice in the stderr tail. `! permission requested: external_directory (<path>); auto-rejecting` becomes `external_path_blocked: opencode refused to read <path> because it is outside <cwd>. Copy the file into the repo, or inline its contents in the prompt.`, printed above the stderr block in every renderer, on stderr, and in `--json` as `warnings[]`. The `opencode-prompting` skill now forbids referencing absolute paths outside the repository root outright — Claude Code stages material under `/private/tmp/claude-501/.../scratchpad`, which opencode will never read.
- The prompt templates the plugin builds (`prompts/review.md`, `prompts/adversarial-review.md`, `prompts/stop-review-gate.md`) now open with a headless-delegation preamble: ignore repository bootstrap rules that tell the delegate to load interactive skills or personas (`pua`, `superpowers`, …) before working, and do not narrate steps. Headless delegates obeyed those rules faithfully — a large share of recorded jobs spent their first turns reading a workflow SKILL.md instead of the work — which fed both the turn-budget and timeout failure classes.
- `task` output now prints the last 5 lines of stderr on successful runs too, not only on failed and incomplete ones. opencode reports an auto-rejected read of a path outside the repo (`! permission requested: external_directory (/private/tmp/*); auto-rejecting`) on stderr and still exits 0, so the cause of a thin or missing answer used to be invisible to the caller — and Claude Code stages large prompts and material in `/private/tmp/claude-501/.../scratchpad` by default.
- Terminal job writes (`task`/`review` verdicts, `cancel`, session teardown) now clear `failureClass`, and a failure label is only ever rendered next to a `failed` status. Reconciliation runs from every reader, so a job could be relabelled `failed (orphaned)` while its own companion was still parsing the run; the record then ended up `completed` *and* `orphaned`, and `status`/`result` printed "the companion process for this job died" underneath a real answer. The child pid is also dropped as soon as opencode exits, so the parse-and-render window runs on the grace clock instead of pointing at a dead process.
- `state.json` and job payload files are now written to a temp file and renamed into place. An in-place overwrite let a concurrent reader see a half-written file, and both `loadState` and `readJobFile` swallow a parse failure — so a torn read silently became "this repository has no jobs" / "no stored output for this job". `saveState` also re-reads after writing and merges again (bounded retry) when it finds records missing, which shrinks — but does not close — the lost-update window; the exclusive lock that closes it remains a follow-up item.
- `saveState` now unions the caller's snapshot with what is on disk before deciding which jobs to prune, so a concurrent writer's job record, stored payload, and open log file can no longer be deleted by a companion holding a stale snapshot.
- Rescue docs (`skills/opencode-cli-runtime/SKILL.md`, `agents/opencode-rescue.md`) now ship explicit `Bash` invocation templates with `timeout: 600000` and a `run_in_background: true` variant for long runs. Forwarders previously inherited Claude Code's 120s default, which killed 16% of `task` calls with `Exit code 143` mid-run.

## 0.1.1

- State resolution now uses the namespaced `OPENCODE_COMPANION_DATA_DIR` env var instead of trusting `CLAUDE_PLUGIN_DATA` from the shared session env, where the last plugin's SessionStart hook to run wins (e.g. the Codex plugin exports it too). Fixes job state landing in another plugin's data directory.

## 0.1.0

Initial release, ported from the Codex plugin for Claude Code (and its Grok port) to the opencode CLI.

- `/opencode:rescue` task delegation with resume, model/variant selection, and background jobs
- `/opencode:review` and `/opencode:adversarial-review` with structured JSON findings
- `/opencode:status`, `/opencode:result`, `/opencode:cancel` job management
- `/opencode:transfer` Claude-session handoff into a seeded opencode session
- `/opencode:setup` readiness report and optional stop-time review gate (Stop hook)
- Session lifecycle hooks that expose the Claude session to the runtime and tear down orphaned jobs
